Before you enable batch translation for a repository, confirm that the following requirements are met: (1) every Markdown file is saved to disk, because unsaved buffers are skipped; (2) the provider is configured and the connection test succeeds; (3) the glossary contains the terms that must stay consistent across documents; (4) the token budget is large enough for the longest section, but not so large that a single failed request discards a whole batch; and (5) the workspace does not contain generated files that should be excluded. Once these conditions hold, translate a small file first, review the preview block by block, and lock any paragraph that a human editor has already approved. If a batch fails, keep the successful results, inspect the error, and retry only the missing blocks. This staged approach makes the first full run predictable and gives reviewers a clear place to start.
