# 支付 API 部署运行手册

本手册涵盖支付 API 的生产部署、部署后的冒烟检查，以及错误率上升时的回滚路径。请在每周发布窗口内，或经事故指挥官批准的紧急变更中使用本手册。

> [!WARNING]
> 月末结账期间禁止部署。如果你不在批准的窗口内阅读本手册，请先停止操作，并在执行任何命令前与支付值班人员确认。

## 前置条件

- 拥有 `payments-prod` 集群的访问权限，并具备发布命名空间中的 `deployer` 角色。
- 已在事故频道中发布状态说明，写明当前版本和目标版本。
- 已在另一个标签页中打开[部署仪表盘](https://example.com/ops/payments)。
- 已通过 `payments-auth login --env prod` 加载凭据；切勿将密钥粘贴到 shell 历史记录中。
- 已取得目标日期对应的变更单批准，且该变更单已链接到事故频道的主题中。

## 部署

1. 确认发布分支在 CI 中通过，且没有任何迁移被标记为必选项。
2. 为本次发布打上 `payments-api-2026.10.3` 标签，并执行 `git push origin payments-api-2026.10.3` 推送该标签。
3. 在 `#payments-releases` 中公布开始时间和标签，然后等待两名成员确认收到。
4. 执行 `kubectl apply -k overlays/prod` 应用本次部署，并观察滚动发布进度，直到所有副本均报告就绪。
5. 执行 `curl -s https://api.example.com/payments/version` 验证版本端点。

冒烟检查通过后才能宣布部署完成。请使用固定的幂等键，向预发端点发送请求：

```json
{
  "account_id": "acct_9f2",
  "amount_cents": 4800,
  "currency": "USD",
  "idempotency_key": "deploy-check-001"
}
```

服务正常时，会在 300 毫秒内返回已创建的发票和请求 id：

```json
{
  "invoice_id": "inv_20481",
  "status": "open",
  "request_id": "req_7c1a"
}
```

结束冒烟检查前，请将请求 id 记录到事故频道，并与仪表盘中的调用链进行比对。

## 错误码

| 错误码 | 含义 | 处理方式 |
| :---: | :--- | :--- |
| `400` | JSON 格式错误或缺少字段 | 修正请求体后重试；无需呼叫值班人员。 |
| `401` | 访问令牌缺失或已过期 | 重新签发令牌、更新密钥，然后重新执行冒烟检查。 |
| `409` | 幂等键重复，但请求体不同 | 复用原始请求体，或等待 24 小时后再重试。 |
| `429` | 超出速率限制 | 退避 60 秒，然后最多重试三次。 |
| `502` | 上游账本服务返回无效响应 | 等待两分钟后重试一次；如果再次出现，请升级处理。 |
| `503` | 上游账本服务不可用 | 发起事故响应，按回滚步骤操作，并通知支付频道。 |

## 回滚

如果 5xx 错误率连续五分钟高于 2%，或冒烟检查连续两次失败，请立即停止发布。然后：

1. 执行 `kubectl scale deploy/payments-api --replicas=0`，将新版本缩容至零。
2. 执行 `kubectl apply -k overlays/prod@payments-api-2026.10.2`，恢复上一个版本标签。
3. 重新执行冒烟检查，并将响应与之前的 `request_id` 进行比对。
4. 在事故频道中记录回滚原因、故障错误码和时间。

> **注意：** 回滚不会撤销数据库迁移。如果 `2026_10_add_invoice_index` 迁移已经执行，请先按照事故模板中链接的迁移指南操作，再恢复流量。

## 获取帮助

请先查看[支付 API 状态页](https://status.example.com/payments)，再通过[值班表](https://example.com/ops/on-call)呼叫支付值班人员。如果账本服务超过 15 分钟仍无法访问，请升级至平台团队。
